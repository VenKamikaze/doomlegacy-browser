# Bugs and quirks found in upstream Doom Legacy 1.48.18 (r1749)

Found while setting up the repository and in F1. Before fixing any of them, check whether a later upstream SVN revision already has: the SVN repository on SourceForge could not be browsed from the cloud container on 19 Nov 2026.

| # | What | Where | Effect | Status |
|---|---|---|---|---|
| L1 | **Sprite columns read far out of bounds on 64-bit builds.** Sprites set `dc_texheight = 0` ("no wrap"). `R_DrawColumn_32` computes `unsigned int heightmask = dc_texheight - 1` = `0xFFFFFFFF`, and when `frac` is negative at the top of a sprite (seen: `frac = -6`), `dc_source[(frac>>FRACBITS)&heightmask]` indexes `dc_source[4294967295]`. On a 32-bit build (upstream's default `ARCH=-march=i686`) and on wasm32, the pointer arithmetic wraps to `dc_source[-1]`, a silent one-byte underread. `r_draw8.c:144` uses a signed `int` mask (still `[-1]`); `r_draw16.c` and `r_draw24.c` are unchecked. | `src/r_draw32.c:42`, `:108`; `src/r_things.c:1437`, `:2973` | **Segfault** on x86_64 the first time the player's weapon sprite is drawn, in a demo or a `-warp`, on Freedoom 1 and 2 and on the shareware `DOOM1.WAD` (`R_DrawColumn_32` ← `R_DrawMaskedColumn` ← `R_DrawVisSprite` ← `R_DrawPlayerSprites`). Also seen at `-O0` (debug build). Blocks the native headless baseline. | **fixed** by [F1](F1-sprite-column-oob.md) (`fix/sprite-column-oob`) |
| L2 | Demo names are cut at 32 bytes. `demoname` is `DEMONAME_LEN` (32) + 5, and `G_DoPlayDemo` copies the `-playdemo` argument with `dl_strncpy(demoname, …, 32)`. | `src/g_game.c:527-528`, `:3981` | A long path, such as `/home/user/doomlegacy-browser/testdata/...`, is silently truncated ("couldn't open lump/file '/home/user/doomlegacy-browser/t.lmp'"). | worked around in `scripts/run-headless.sh` |
| L3 | `-playdemo NAME` first tries `NAME` as a lump (`W_CheckNumForName`, which compares only 8 characters), then as a file. | `src/g_game.c:3983` | `freedoom1-demo1.lmp` loaded Freedoom's `FREEDOOM` lump and failed with "Incompatible demo (version 48)". | worked around by the short file names `fdNdemoM.lmp` |
| L4 | When `-playdemo` cannot open the demo, the game falls back to the title loop instead of quitting, although `singledemo` is set. | `src/g_game.c:3998-4001` (`goto no_demo`) | A scripted run with a bad demo never ends by itself; only the timeout stops it. | noted |
| L5 | The Makefile's dependency rules all write one temp file, `$(DD)/sed.dep`, so `make -jN` fails on a fresh build with `mv: cannot stat '.../dep/sed.dep'`. | `src/Makefile:~1749` | Parallel first builds fail. | worked around in `scripts/build-native.sh` (serial `make depend` first) |
| L6 | `make_options_nix`, which the Makefile copies on a first run, sets `ARCH=-march=i686`. | `make_options_nix` | Wrong on x86_64 hosts. | worked around (`ARCH=` in `scripts/make_options_native`) |
| L7 | The game runs at 100% CPU under `SDL_VIDEODRIVER=dummy`: there is no frame wait without vsync. | the main loop (not traced yet) | Matters for the browser, where the same pacing problem will show. | noted |
| L8 | `R_RenderSegLoop` reads `finetangent[]` past its end: `angf = ANGLE_TO_FINE(rw_centerangle + x_to_viewangle[rw_x])` reached 4,101 of 4,096 entries. This is the vanilla Doom quirk; there, the read runs into `finesine`. | `src/r_segs.c:2447-2448`, `src/tables.c:125` | ASan `global-buffer-overflow` (20 bytes past `finetangent`) in `d1demo3` and `fd2demo1`. What it reads depends on how the compiler lays out globals, so native and wasm may draw a slightly different wall-texture column. It does not affect gameplay. | noted (found by ASan in F1) |
| L9 | The zone allocator hands out blocks aligned to 4 bytes on 64-bit builds; structs holding pointers need 8. | `src/z_zone.c:858-958`, then every `Z_Malloc` user (`r_bsp.c:917`, `p_mobj.c:2844`, `p_setup.c:384`, ...) | Hundreds of UBSan "misaligned address" reports per run. x86_64 and wasm tolerate it; strict-alignment CPUs would not. | noted (UBSan, F1) |
| L10 | Left shifts of negative values (undefined behaviour in C), for example `R_ExecuteSetViewSize` and `R_AddSingleSpriteDef`. | `src/r_main.c:1078`, `src/r_things.c:625-626` | gcc and clang give the expected two's-complement result, so nothing shows today. | noted (UBSan, F1) |
| L11 | The 16 bpp column drawer masks sprite columns with `& 127` (vanilla behaviour), while the 8/24/32 bpp drawers read `dc_source[-1]` at the same point. | `src/r_draw16.c:96` | The top pixel of some sprite columns can differ between 16 bpp and other depths. Cosmetic. | noted |
